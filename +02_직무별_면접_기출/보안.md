## Q1. [개념/이론] SROS2(Secure ROS 2)의 3대 핵심 요소와 DDS Security 표준 구현 메커니즘은? [빈출]

**답변 요약**

* **인증(Authentication)**: X.509 공개키 인프라(PKI) 인증서를 통해 통신에 참여하는 로봇 노드의 신원을 상호 검증함.
* **접근 제어(Access Control)**: 서명된 권한(Permissions) XML 문서를 기반으로 특정 노드가 발행(Publish) 또는 구독(Subscribe)할 수 있는 ROS 2 토픽/서비스/액션을 제한함.
* **암호화(Cryptographic)**: AES-GCM 대칭키 암호화를 적용하여 메시지 기밀성(Confidentiality)과 변조 방지 무결성(Integrity)을 하부 DDS 통신 계층에서 보장함.

## Q2. [시스템/응용] 로봇 제어 필드버스(CAN, Industrial Ethernet)의 보안 취약점과 SecOC 적용 방안은? [빈출]

**답변 요약**

* **취약점**: CAN 통신은 브로드캐스트 특성상 인증 및 암호화가 없어 패킷 스니핑, 재전송(Replay) 공격, ID 스푸핑 기반 악의적 모터 토크 주입에 노출됨.
* **방어 대책**: AUTOSAR 표준의 SecOC(Secure On-Board Communication)를 도입함. 하드웨어 보안 모듈(HSM)을 통해 CAN 페이로드마다 대칭키(AES-128 CMAC) 기반 메시지 인증 코드(MAC)와 신선도 값(Freshness Value)을 결합 전송하여 패킷 위변조 및 재전송 공격을 차단함.

## Q3. [개념/이론] 임베디드 로봇 제어기의 Secure Boot 동작 순서와 Root of Trust(RoT)의 역할은? [빈출]

* **답변 요약**: 변경이 제한된 초기 부트 코드와 신뢰할 키·키 해시를 기점으로 다음 단계 이미지의 서명을 검증함. 키 해시를 OTP/eFuse 등에 저장하는 방식은 SoC 설계에 따라 달라짐.
* **주의 조건**: 검증 대상·실패 시 동작·키 갱신·복구 경로를 확인함. Secure Boot만으로 실행 중 취약점이나 서명된 취약 버전의 사용까지 방지되는 것은 아니므로 업데이트와 버전 정책을 함께 설계함.

## Q4. [실무/트러블슈팅] 로봇 무선 펌웨어 업데이트(OTA) 파이프라인의 위협 모델과 안전한 배포 설계는? [빈출]

**답변 요약**

* **전송 구간 보호**: TLS 1.3 기반 상호 인증(mTLS) 채널을 통해 OTA 서버에서 바이너리를 수신하여 중간자 공격(MITM)을 방어함.
* **무결성 및 신뢰성 검증**: 다운로드된 펌웨어 헤더의 비대칭키 전자서명(ECDSA/RSA)을 로컬 RoT 공개키로 검증함.
* **다운그레이드 방어**: 보안 패치 이전의 취약한 구버전으로 되돌리는 공격을 막기 위해 펌웨어 내부 보안 버전 카운터와 하드웨어 안티 롤백(Anti-rollback) eFuse 값을 대조함. Dual-bank(A/B 파티션) 구조로 업데이트 실패 시 안전 복구를 지원함.

## Q5. [시스템/응용] AMR 및 서비스 로봇의 무선 통신망(Wi-Fi, 5G) 보안 구성 시 WPA3 Enterprise 적용법은? [빈출]

**답변 요약**

* 공유 비밀번호(PSK) 탈취 및 사전 대입 공격을 차단하기 위해 802.1X EAP-TLS 인증 기반 WPA3 Enterprise를 구축함.
* 로봇 디바이스마다 고유한 기기 인증서와 비공개키를 발급하고 RADIUS 서버를 통해 상호 인증함. 기밀성 보장을 위해 192비트 보안 스위트(GCMP-256)를 적용하고, 관리 프레임 보호(PMF, 802.11w)를 의무화하여 와이파이 연결 해제(Deauthentication) DoS 공격을 차단함.

## Q6. [개념/이론] STRIDE 위협 모델링과 로봇 소프트웨어 침투 테스트(Penetration Testing) 절차는? [빈출]

**답변 요약**

* **STRIDE 분석**: 스푸핑(센서 노드 사칭), 변조(제어 명령 패킷 변경), 부인(작업 로그 누락), 정보 유출(카메라 피드 탈취), 서비스 거부(통신 버퍼 플러딩), 권한 상승(루트 쉘 획득) 6개 범주로 시스템 데이터 흐름도(DFD)를 분석함.
* **침투 테스트**: Nmap을 통한 개방형 포트 스캔, Wireshark를 이용한 패킷 덤프 분석, ROS 2 토픽 및 API 입력단 대상 퍼징(Fuzzing) 도구를 구동하여 메모리 오염(Buffer Overflow) 및 비인가 접근 취약점을 도출하고 보안 패치를 적용함.

## Q7. [실무/트러블슈팅] Linux 기반 로봇 OS 하드닝(OS Hardening) 및 컨테이너 샌드박싱 기법은? [빈출]

**답변 요약**

* **권한 최소화**: ROS 2 프로세스가 `root` 대신 전용 비특권 계정(`robot-user`)으로 실행되도록 권한을 분리함. SSH 루트 로그인 및 불필요한 데몬 포트를 비활성화함.
* **강제 접근 제어(MAC)**: AppArmor 또는 SELinux 정책 프로파일을 정의하여 로봇 프로세스가 지정된 장치 드라이버(`/dev/ttyUSB*`, `/dev/can*`) 및 설정 디렉토리에만 접근하도록 격리함.
* **커널 파라미터 튜닝**: `sysctl`을 통해 IP 포워딩 제한, SYN 쿠키 활성화, ASLR(Address Space Layout Randomization) 강제 적용을 수행함.

## Q8. [시스템/응용] 로봇 제어기 내 하드웨어 보안 모듈(TPM 2.0, HSM) 및 ARM TrustZone의 역할은? [빈출]

* **답변 요약**: TPM·HSM은 키 보호와 암호 연산을 지원하며, 추출 저항성·지원 알고리즘·인증 범위는 제품마다 다름. TrustZone은 일반 실행 영역과 보안 실행 영역의 격리를 지원함.
* **주의 조건**: 하드웨어 격리만으로 모든 공격이 차단되거나 비상정지 같은 기능안전 요구가 충족되지는 않음. 키 접근 정책, 보안 영역의 코드, 업데이트·디버그 경로와 별도의 안전 설계를 함께 검토함.

## Q9. [실무/트러블슈팅] 로봇 관제 웹 대시보드(FMS) 대상 OWASP Top 10 취약점 방어 설계는? [빈출]

**답변 요약**

* **SQL Injection**: 동적 쿼리 조립을 배제하고 ORM 프레임워크 또는 파라미터화된 쿼리(Prepared Statement)를 강제함.
* **XSS**: 입력값 검증과 출력 데이터 HTML 인코딩을 적용하고, Content Security Policy(CSP) 헤더를 선언하여 인라인 스크립트 실행을 제한함.
* **CSRF**: 모든 상태 변경 API 요청에 유효성 검증용 CSRF 토큰을 발급하거나 세션 쿠키에 `SameSite=Strict` 및 `Secure`, `HttpOnly` 속성을 설정함.
* **인증 관리**: 관제 대시보드 접근 시 다중 요소 인증(MFA) 및 JWT 토큰 만료 주기 단축을 적용함.

## Q10. [실무/트러블슈팅] ROS 2 토픽 플러딩(Topic Flooding) 및 DoS 공격 발생 시 트래픽 완화 대책은? [빈출]

* **답변 요약**: 발행 권한과 네트워크 접근을 제한하고, 발행 빈도·대역폭·자원 사용을 감시함. 과부하 시 통신 제한과 제어 기능의 자원 보호를 함께 설계함.
* **QoS 구분**: Depth는 보관할 샘플 수, Deadline은 기대 메시지 간격 위반 감지, Lifespan은 메시지 유효기간에 관한 설정임. Deadline은 악성 패킷을 식별·폐기하는 기능이 아님.
* **주의 조건**: XDP 등 조기 필터링도 처리 비용이 있으며 공격 경로·장치 성능에 맞춰 측정함. QoS만으로 인증·접근 제어·속도 제한을 대체하지 않음.
* **참고**: [ROS 2 QoS 설계](https://design.ros2.org/articles/qos_deadline_liveliness_lifespan.html)

## Q11. [규정대응] EU 사이버 복원력 규정(CRA)의 주요 의무와 적용 시점은? [빈출]

* **답변 요약**: CRA는 적용 대상 디지털 요소 제품에 보안 설계·취약점 처리·적합성 평가 의무를 부과함. 제품 유형·예외·경제주체의 역할을 먼저 확인함.
* **보고 구분**: 인지한 실제 악용 취약점과 제품 보안에 영향을 미치는 중대한 사고는 24시간 조기 경보와 72시간 본 보고를 구분함. 최종 보고 기한도 취약점과 사고에 따라 다르며, 모든 발견 취약점을 일률적으로 24시간 내 보고한다는 뜻은 아님.
* **적용 시점**: 보고 의무는 2026-09-11, 주요 제품 의무의 전면 적용은 2027-12-11로 구분함. 지원 기간은 원칙적으로 최소 5년이며 예상 사용 기간이 더 짧은 경우 등 규정 조건을 확인함.
* **꼬리 질문**: 사용하는 라이브러리에서 CVE가 발견되면 실제 영향·악용 여부·보고 대상·패치 검증을 어떻게 판단하는가?
* **참고**: [EU CRA 공식 요약](https://digital-strategy.ec.europa.eu/en/policies/cra-summary) — 2026-09-27 확인함.

## Q12. [시스템/응용] 로봇 SW 공급망 보안을 위한 SBOM(SPDX/CycloneDX) 생성 및 CVE 자동 탐지 파이프라인은? [빈출]

* **답변 요약**: 빌드 산출물의 구성요소·버전을 SBOM으로 기록하고 취약점 데이터와 지속 대조함. SPDX·CycloneDX 등 형식과 탐지 도구는 대상 언어·이미지에 맞춰 선택함.
* **대응 기준**: CVSS뿐 아니라 실제 포함 버전·취약 기능의 사용·노출 경로·악용 가능성·완화 대책을 검토함. 수정 후 기능·보안·운영 검증을 거쳐 배포하고 예외 승인과 잔여 위험을 기록함. 탐지 도구의 결과만으로 영향이나 패치 안전성이 확정되지는 않음.

## Q13. [시스템/응용] 스마트 팩토리 환경에서 로봇 OT 망분리(Purdue Model) 및 제로 트러스트(Zero Trust) 구축은? [빈출]

**답변 요약**

* **Purdue Model 기반 분리**: 레벨 1~2(로봇 제어기, 센서, PLC) 영역과 레벨 4~5(전사 IT, ERP) 영역 사이에 산업용 차세대 방화벽(NGFW) 및 비무장지대(DMZ)를 구성함.
* **제로 트러스트 적용**: "내부 네트워크는 안전하다"는 가정을 배제함. 외부 관제 서버와 로봇 간 통신 시에도 데이터 다이오드(Data Diode) 또는 단방향 게이트웨이를 적용하여 직접 접근을 차단하고, 모든 세션에 대해 개별 인증서 기반 상호 검증 및 최소 권한 접근(Least Privilege)을 강제함.

## Q14. [실무/트러블슈팅] 로봇 운영 로그의 무결성 보장을 위한 암호학적 기법 및 중앙 SIEM 연동 체계는? [빈출]

**답변 요약**

* **로컬 로그 변조 방지**: 로그 레코드 생성 시 이전 로그의 해시값을 포함하는 해시 체인(Hash-chain) 구조를 적용하거나, Write-Once-Read-Many(WORM) 저장소를 설정하여 공격자의 흔적 삭제 및 덮어쓰기 시도를 감지함.
* **중앙 관제 전송**: Fluentbit/Logstash 경량 에이전트를 통해 mTLS 암호화 터널로 중앙 SIEM(Elasticsearch/Splunk)에 준실시간 포워딩함. 로그 전송 단절이나 비정상적인 삭제 요청 발생 시 보안 운영 센터(SOC)로 즉각 알람을 트리거함.

## Q15. [시스템/응용] 하드웨어 레벨의 물리적 해킹 공격(JTAG/UART, Side-channel) 차단 대책은? [빈출]

**답변 요약**

* **디버깅 포트 비활성화**: 양산 단계에서 온칩 eFuse를 물리적으로 절단(Blow)하여 JTAG 및 직렬 UART 디버그 포트 인터페이스를 영구 비활성화함으로써 비인가 메모리 덤프를 차단함.
* **물리적 개봉 감지**: 제어기 케이스에 탬퍼 스위치(Tamper Switch)를 배치하여 외피 개방 시 HSM 내부의 암호화 키 메모리를 즉각 소거(Zeroization)하도록 회로를 구성함.
* **부채널 공격 방어**: 전력 분석(DPA) 방지를 위해 하드웨어 암호화 가속기 내부의 연산 시간에 마스킹(Masking) 및 랜덤 지연 노이즈를 삽입함.
