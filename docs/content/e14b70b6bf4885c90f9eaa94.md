# [코딩테스트] 로봇/AI SW 개발 직무 준비 가이드

> 시험 안내를 먼저 확인하고, 문제의 조건에 맞는 풀이를 구현·검증하는 연습에 집중함. 로봇 직무라는 이유만으로 로봇 전용 알고리즘이 출제된다고 가정하지 않음.

---

## 1. 시험 형식과 언어 선택 기준

* **안내 확인**: 허용 언어와 버전, 사용 가능한 라이브러리·도구, 제한 시간·메모리, 제출 방식을 먼저 확인함. 표준 입출력으로 작성하는지, 주어진 함수를 완성하는지도 구분함.
* **유형 구분**: 알고리즘 문제 풀이, 실시간 코딩 면접, 직무 과제는 준비 범위가 다름. 공고와 전형 안내에 맞춰 연습함.
* **언어 선택**: 언어가 지정되어 있으면 해당 언어를 준비함. 선택할 수 있다면 정확히 구현하고 디버깅할 수 있는 언어를 우선 검토하며, 직무 요구사항과 실행 제한도 함께 고려함.

### (1) C++ 준비 범위

* **공통 문제 풀이**: `vector`, `string`, `queue`, `priority_queue`, `map`, `unordered_map` 등의 기본 사용법과 연산 비용을 익힘. 정렬 기준, 참조·복사, 정수 범위, 인덱스 접근을 점검함.
* **직무 과제·면접 보완**: 메모리 소유권, 객체 수명, 스마트 포인터 등은 요구된 과제와 역할에 맞춰 준비함. 모든 알고리즘 시험이 포인터 연산이나 스마트 포인터를 평가한다고 가정하지 않음.
* **언어와 직무 구분**: 제어·임베디드 직무라도 시험 언어와 범위는 공고별로 확인함. C가 지정된 경우에는 C++ 라이브러리를 전제로 준비하지 않으며, 안내에 맞춰 배열·포인터·버퍼 처리 등을 연습함.

### (2) Python 준비 범위

* **공통 문제 풀이**: `list`, `dict`, `set`, 정렬, `collections.deque`, `heapq` 등의 사용법과 연산 비용을 익힘. 짧은 코드보다 정확성과 설명 가능성을 우선함.
* **성능 점검**: 반복문 안에서 슬라이싱·복사·선형 탐색이 반복되는지 확인함. 깊은 재귀나 큰 자료구조를 사용할 때 실행 환경의 제약을 검토함.
* **라이브러리 확인**: AI 직무라고 해서 NumPy·PyTorch 등을 사용할 수 있다고 가정하지 않음. 허용된 라이브러리와 버전으로 연습함.

## 2. 공통 알고리즘과 직무별 심화 주제

아래는 준비 범위를 정리하기 위한 목록이며, 로봇/AI 기업의 출제 빈도 순위가 아님. 공통 자료구조와 알고리즘을 익힌 뒤 실제 전형에 맞춰 심화 범위를 조정함.

### (1) 공통 문제 풀이에서 점검할 다섯 영역

1. **배열·문자열·해시·정렬**

    * 빈도 집계, 중복 처리, 문자열 파싱, 정렬 기준을 연습함. 자료를 어떤 형태로 저장해야 필요한 연산을 효율적으로 수행할 수 있는지 설명함.

2. **스택·큐·우선순위 큐**

    * 후입선출, 선입선출, 우선순위에 따른 추출을 구분함. Python의 `heapq` 기본 연산은 최솟값을 꺼내므로 필요한 우선순위와 맞는지 확인함. 힙에 저장된 배열 전체가 정렬된 상태라고 가정하지 않음. [Python heapq 공식 문서](https://docs.python.org/3/library/heapq.html)

3. **BFS·DFS와 그래프·격자 탐색**

    * 방문 상태, 연결 관계, 경계 조건, 중복 방문 방지를 연습함. BFS는 간선 비용이 같은 경우 최소 이동 횟수를 찾는 데 사용할 수 있으며, 일반적인 DFS가 최단 경로를 보장하는 것은 아님.
    * 격자에서 이동 가능 여부를 확인하는 연습과 실제 로봇의 형상·운동 제약을 고려한 충돌 검사는 구분함.

4. **이진 탐색·그리디·동적 계획법**

    * 이진 탐색은 정렬이나 판정 조건의 단조성이 성립하는지 확인함. 그리디는 선택이 최적해로 이어지는 근거를 설명하고, 동적 계획법은 상태·전이·초기값·계산 순서를 정의함.

5. **누적합·투 포인터·슬라이딩 윈도우**

    * 구간 합, 연속 구간, 반복 계산 줄이기를 연습함. 두 포인터를 한 방향으로 움직여도 되는지 문제 조건을 확인함. 음수가 포함된 구간 합 문제에 양수 전제의 풀이를 그대로 적용하지 않음.
    * 고정 길이 구간의 이동 평균은 응용 예시 중 하나이며, 모든 노이즈 필터링 문제를 같은 방식으로 해결할 수 있다고 가정하지 않음.

### (2) 직무 과제나 면접 범위에 따라 추가할 주제

* **경로 계획**: Dijkstra는 간선 비용이 음수가 아닌 경우를 전제로 학습함. A*는 누적 비용과 목표까지의 추정 비용을 함께 사용하므로, 휴리스틱과 중복 상태 처리 방식에 따른 최적성 조건도 확인함. 알고리즘 이름만 외우기보다 적용 조건을 설명함. [UC Berkeley의 A* 설명](https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html)
* **좌표 변환·기하학**: 좌표계, 각도 단위, 행렬 곱 순서, 회전 표현을 점검함. 쿼터니언은 성분 순서와 회전 적용 규약도 확인함. 모든 일반 코딩테스트의 필수 범위로 간주하지 않음.
* **임베디드·시스템 구현**: 요구된 경우 비트 연산, 버퍼 경계, 상태 머신, 통신 데이터 파싱 등을 보완함.
* **AI·데이터 과제**: 요구된 경우 데이터 전처리, 배열 차원, 평가 코드와 재현 가능한 실행 방법을 준비함.

## 3. 풀이 설계·구현·검증 원칙

### (1) 입력 조건으로 계산량과 메모리를 추정함

`N` 하나만 보고 허용되는 복잡도를 확정하지 않음. 테스트 케이스 수, 그래프의 정점·간선 수, 격자 크기, 시간·메모리 제한, 언어와 실제 연산 비용을 함께 검토함.

* **계산량 예시**: `N = 100,000`이면 `N^2`는 약 100억, `N log2 N`은 약 170만 규모임. 이는 증가 양상을 비교하는 값이며, 실제 명령어 수나 통과 시간을 보장하는 기준은 아님.
* **전체 비용 확인**: 정렬, 자료 복사, 문자열 처리, 입력 읽기와 반복 호출 비용을 포함함. 이진 탐색 한 번이 `O(log N)`이어도 입력·전처리를 포함한 전체 풀이가 `O(log N)`인 것은 아님.
* **메모리 확인**: `R × C` 격자, 방문 배열, 큐·힙, 재귀 호출에 필요한 메모리를 함께 고려함. 시간 복잡도가 적절해도 메모리 제한을 넘을 수 있음.

### (2) 문제 해석부터 검증까지 순서를 잡음

1. 입력·출력, 제약, 목표를 정리함. 실시간 면접에서는 모호한 조건을 질문하고, 온라인 시험에서는 명시된 조건과 제공된 안내를 기준으로 풀이함.
2. 간단한 풀이부터 생각한 뒤 정확성과 비용을 검토함. 더 효율적인 방법이 필요하면 자료구조와 알고리즘을 바꿈.
3. 변수명과 함수의 역할을 분명하게 작성함. `i`, `j` 같은 짧은 반복 인덱스는 사용할 수 있으며, 의미를 이해하기 어려운 축약을 줄임.
4. 예제와 직접 만든 경계 입력으로 결과를 확인함. 제출 직전에 바꾼 코드도 다시 실행함.

풀이가 막히면 남은 시간과 다른 문제를 확인해 우선순위를 조정함. 실시간 면접에서는 접근 방법·복잡도·검증 결과 등 주요 판단을 공유함.

### (3) 제출 전 경계 조건을 확인함

문제에서 허용하는 입력 범위 안에서 다음 항목을 점검함. 허용되지 않은 입력에 대한 방어 코드를 무조건 추가할 필요는 없음.

* 최소·최대 크기, 빈 입력이 허용되는 경우, 원소 하나인 경우를 확인함.
* 중복값, 모든 값이 같은 경우, 음수·0이 허용되는 경우를 확인함.
* 인덱스 범위, 시작점과 도착점이 같은 경우, 경로가 없는 경우, 순환과 중복 방문을 확인함.
* 정수 오버플로, 0으로 나누기, 문제에서 요구하는 부동소수점 오차 허용 범위를 확인함.
* 여러 테스트 케이스 사이의 상태 초기화, 입력 원본 변경, 반환 형식과 불필요한 출력 여부를 확인함.
* 최대 입력에서의 실행 시간·메모리와 재귀 깊이를 점검함. 예제 통과만으로 전체 정답을 확신하지 않음.

## 4. 연습 플랫폼과 복습 방법

### (1) 백준: 이용 상태를 먼저 확인함

* **확인 상태**: 2026-09-27 기준 [백준 공식 홈페이지](https://www.acmicpc.net/)에 '채점 서비스 준비 중'이라는 안내가 표시됨. 기존 문제집과 채점 기능을 바로 사용할 수 있다고 가정하지 않고, 이용 전 공식 공지를 다시 확인함.
* **대체 연습 방향**: 격자 이동, 조건별 상태 변화, 배열 회전 등 구현 문제는 아래 플랫폼에서도 찾아 연습함. 이런 문제 풀이만으로 실제 로봇 제어·시뮬레이션 역량이 검증되었다고 보지는 않음.

### (2) 프로그래머스: 유형별 학습과 제출 형식 연습

* **공식 자료**: [코딩테스트 고득점 Kit](https://school.programmers.co.kr/learn/challenges?tab=algorithm_practice_kit)에서 해시, 스택·큐, 정렬, 탐색 등 유형별 문제를 확인함.
* **활용 방법**: 현재 수준에 맞는 문제부터 풀고, 제공되는 함수의 인자와 반환값을 맞추는 연습에 활용함. 특정 난이도를 풀면 모든 기업 시험에 대비된다고 가정하지 않으며, 실제 시험의 제출 방식은 별도로 확인함.

### (3) LeetCode: 자료구조·알고리즘과 풀이 설명 연습

* **공식 자료**: [LeetCode 75](https://leetcode.com/studyplan/leetcode-75/) 등을 참고해 준비할 문제를 선택함. 수학·기하 문제에만 집중하기보다 부족한 공통 유형을 먼저 점검함.
* **활용 방법**: 풀이의 정확성, 시간·공간 복잡도, 다른 접근의 장단점을 비교함. 플랫폼의 실행 시간 순위만으로 풀이의 우수성을 판단하지 않음.

### 공통 복습 흐름

직접 풀이 → 실패 입력과 원인 기록 → 필요한 개념·해설 확인 → 해설을 덮고 재구현 → 다른 입력으로 검증하는 흐름으로 연습함. 통과한 문제 수뿐 아니라 혼자 다시 풀 수 있는지, 알고리즘의 적용 조건과 복잡도를 설명할 수 있는지도 확인함. 실제 시험을 앞두고는 안내된 언어·버전·도구·시간 제한에 맞춰 연습함.
