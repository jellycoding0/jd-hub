# [서류팁] 직무 역량이 돋보이는 자기소개서 및 포트폴리오 작성법

---

## 1. 서류 작성 핵심 원칙: "직무에 맞는 경험을 근거로 설명하기"

* **공고의 요구 역량과 경험 연결하기**: 지원 공고에서 핵심 업무와 요구 역량을 추린 뒤, 이를 보여줄 수 있는 경험을 우선 배치할 것. 같은 프로젝트라도 제어 직무에는 제어기 설계와 실험 결과를, 임베디드 직무에는 실행 시간·통신·메모리 제약을 중심으로 설명할 수 있음.
* **성과는 확인 가능한 근거로 제시하기**: 측정한 결과가 있다면 동일한 조건의 전후 수치(예: 처리 시간 15% 단축)를 제시할 것. 수치가 없다면 구현 범위, 테스트 결과, 해결한 문제와 한계를 구체적으로 설명할 것. 측정하지 않은 개선율은 임의로 작성하지 말 것.
* **문제 해결 과정 중심 기술**: 기능 나열만으로는 본인의 판단과 기여를 파악하기 어려움. 프로젝트 중 겪은 기술적 문제(특이점 부근의 계산 불안정, GPS 수신 불량, 통신 지연 등)와 원인 분석, 대안 비교, 직접 시도한 해결 과정을 설명할 것.
* **팀과 시스템에 대한 기여 설명**: 본인이 구현하거나 개선한 부분이 전체 시스템 안정성, 메모리 효율, 로봇 작업 시간 등 팀과 제품에 어떤 기여를 했는지 서술할 것.

## 2. 경험 분해(4P) 기반 자소서 작성 예시

이 문서에서는 경험을 빠짐없이 정리하기 위한 틀로 **목적(Purpose) - 문제(Problem) - 해결 과정(Process) - 성과(Performance) + 적용점(Insight)** 구조를 사용함. 이를 바탕으로 지원서의 질문과 글자 수에 맞게 필요한 내용을 골라 작성할 것.

> 아래는 작성 구조를 설명하기 위한 가상 예시임. 기술 내용과 수치는 본인이 수행하고 검증한 경험에 맞게 작성할 것. `○`는 실제 기록으로 채우는 자리이며, 측정 기록이 없다면 확인 가능한 구현·검증 내용으로 바꿀 것.

### [예시 1] DLS 기반 특이점 부근의 역기구학 계산 안정화

* **핵심 헤드라인**: [DLS 적용과 비교 실험으로 다관절 로봇 시뮬레이터의 역기구학 계산 안정화]
* **Purpose (배경 및 목표)**: 인턴십 중 다관절 로봇의 모션 검증을 위한 자체 시뮬레이션 툴 개발을 담당함.
* **Problem (문제 상황)**: 특이점(Singularity) 부근에서 자코비안의 조건이 나빠져, 역기구학 계산으로 얻은 관절 속도가 과도하게 커지는 문제가 발생함.
* **Process (해결 과정)**: 관련 논문을 검토해 Damped Least Squares(DLS) 알고리즘을 적용함. Python 환경에서 동일한 시험 궤적으로 감쇠 계수별 관절 속도와 위치 오차를 비교하고, 속도 증가를 억제하면서 허용 오차를 만족하는 계수를 선정함. 팀원이 결과를 확인할 수 있도록 PyQt 기반 GUI를 제작함.
* **Performance (최종 성과)**: 설정한 시험 궤적 ○개에서 관절 속도 제한 초과가 ○회에서 ○회로 감소했으며, 말단 위치의 최대 오차는 ○mm로 측정됨. 결과는 해당 시뮬레이션 조건에서 확인한 범위로 제시함.
* **Insight (적용점)**: 관절 속도와 위치 오차를 함께 평가하며 알고리즘 설정의 장단점을 비교하는 방법을 익힘. 시험 궤적과 평가 코드를 정리해 팀원이 같은 조건으로 결과를 재현할 수 있도록 함.

> **기술 표현 주의**: DLS를 적용해 특이점 부근의 계산을 안정화한 것과, 경로를 바꿔 특이점 자체를 회피한 것은 구분해서 설명할 것.

### [예시 2] EKF 기반 센서 융합을 통한 실외 로봇 위치 추정 정밀도 향상

* **핵심 헤드라인**: [동일 주행 로그 평가에서 센서 융합으로 최대 위치 오차 75% 감소]
* **Purpose (배경 및 목표)**: 실외 자율주행 로봇의 정밀 주행을 위한 위치 추정(Localization) 알고리즘 최적화 프로젝트를 수행함.
* **Problem (문제 상황)**: 초기 야외 주행 테스트 중 GPS만 사용한 위치 추정에서 고층 건물 주변의 수신 불안정으로 최대 위치 오차 1.2m가 관측됨.
* **Process (해결 과정)**: 확장 칼만 필터(EKF)를 적용해 GPS와 IMU 데이터를 융합함. 프로세스 잡음 공분산 Q와 측정 잡음 공분산 R을 구분해 설정하고, 센서 측정과 주행 로그를 바탕으로 조정함. GPS 수신이 끊긴 구간에서는 IMU 기반 예측으로 위치 추정을 이어가며, 누적 오차와 GPS 수신 복구 후의 보정 과정을 평가함.
* **Performance (최종 성과)**: 기준 위치가 확보된 동일한 주행 로그의 평가 구간에서 GPS만 사용한 경우와 센서 융합 결과를 비교함. 최대 위치 오차가 1.2m에서 0.3m로 감소해 75% 개선됨. 실제 작성 시에는 기준 위치의 측정 방법, 평가 구간, GPS 수신 중단 시간과 반복 시험 횟수를 함께 명시할 것.
* **Insight (적용점)**: 센서별 특성과 수신 상태에 따라 추정 결과가 달라지는 점을 확인함. GPS 수신 중단 중에도 위치 추정은 이어갈 수 있지만, 시간이 지나면 오차가 누적될 수 있으므로 검증한 조건과 한계를 함께 설명함.

## 3. 로봇/AI 직무 포트폴리오(Portfolio) 작성 가이드

### (1) 포트폴리오 구성 예시

기업의 제출 형식·분량·용량 기준을 우선 확인할 것. 별도 기준이 없다면 지원 직무와 관련성이 높은 프로젝트 2~3개를 중심으로 아래 구성을 참고할 수 있음. 프로젝트 수를 채우기 위해 관련성이 낮은 경험을 추가하기보다, 본인의 역할과 판단을 설명할 수 있는 경험을 선택할 것.

1. **표지 및 핵심 요약 (예: 1장)**

    * 이름, 지원 세부 직무(제어, 로봇 인지, 엣지 AI 등), 실제 활용한 핵심 기술 스택(C++, Python, ROS 2, PyTorch 등).
    * 대표 프로젝트별로 지원 직무와 연결되는 본인의 역할과 검증 결과를 한 줄로 요약.

2. **대표 프로젝트 상세 페이지 (예: 프로젝트당 2~3장)**

    * **개요 및 역할**: 개발 기간, 참여 인원, 본인이 담당한 설계·구현·검증 범위, 협업 방식, 사용 도구 및 프레임워크.
    * **시스템 구조 시각화**: 하드웨어 블록 다이어그램, 소프트웨어 구조도, ROS 2 노드·토픽 흐름도 등 프로젝트에 맞는 그림.
    * **핵심 트러블슈팅**: 발생한 기술적 문제 → 공학적 접근(비교 실험/수식/코드) → 확인한 결과와 한계.
    * **검증 근거**: 수치를 제시할 경우 측정 환경, 비교 기준, 시험 횟수, 지표 정의(최대 오차·평균 오차 등)를 함께 기재. 시뮬레이션 결과와 실제 로봇 시험 결과도 구분.
    * **시각 자료**: 시뮬레이션(Isaac Sim, Gazebo) 화면, 실제 하드웨어 구동 사진, 데모 영상 링크/QR 코드 첨부.

3. **기술 블로그 및 저장소 (예: 1장)**

    * 구현 내용과 학습 과정을 확인할 수 있는 GitHub, 기술 블로그 링크 정리. 프로젝트 설명, 실행 방법, 본인이 작성한 부분을 찾기 쉽게 안내.

---

### (2) 본인의 역량을 명확히 전달하는 포트폴리오 작성 팁 5가지

1. **시각적 구조화: 도식과 구동 영상 적극 활용**

    * 소프트웨어 모듈 구조도, 데이터 흐름도 등으로 시스템 구성을 설명할 것. 데모 영상은 구현 결과를 빠르게 전달하는 데 도움이 됨. 영상만으로 확인하기 어려운 시험 조건과 성능 지표는 별도로 설명할 것.

2. **팀 성과와 본인의 담당 범위 구분**

    * 팀 전체 성과와 본인이 담당한 범위를 구분할 것. 근거가 모호한 기여도 비율보다, "EKF 노드 구현과 센서 시간 동기화, 주행 로그 평가를 담당"처럼 구체적으로 설명하면 후속 질문에도 답하기 쉬움.

3. **결과와 측정 조건을 함께 제시**

    * 실제 측정 기록이 있다면 "동일한 하드웨어·입력 해상도에서 영상 처리량 18 FPS → 32 FPS"처럼 비교 조건과 지표를 함께 제시할 것. 수치가 없다면 "통신 끊김을 재현하고 재연결 동작을 검증함"처럼 구현·시험 내용과 결과를 설명할 것. 실패하거나 검증하지 못한 범위도 구분할 것.

4. **트러블슈팅의 깊이 보여주기**

    * 문제 원인 분석, 여러 대안 비교, 최종 기술 채택 이유를 설명할 것. "EKF를 사용함"에 그치지 않고 왜 선택했는지, 다른 방법과 비교해 어떤 장단점이 있었는지, 어떤 조건에서 검증했는지 기술할 것.

5. **제출 파일 최적화**

    * 기업이 지정한 형식과 용량을 우선 따를 것. 별도 기준이 없다면 PDF로 내보내고, 이미지 압축 후에도 글자와 그래프가 읽히는지 확인할 것. 제출 파일에서 링크·QR 코드가 작동하는지, 영상과 저장소를 열람할 수 있는지도 확인할 것.
