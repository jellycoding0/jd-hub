# [실무면접] 로봇/AI 기술 및 실무 면접 준비 가이드

> 실무 면접에서는 무엇을 만들었는지와 함께, 왜 그렇게 판단했고 어떻게 검증했는지를 설명하는 연습이 필요함.

---

## 1. 1차 실무 면접 개요 및 핵심 평가 요소

* **면접관**: 파트장, 테크 리드, 담당 엔지니어 등 입사 후 협업할 수 있는 현업 구성원이 참여할 수 있음. 구성과 진행 방식은 회사와 채용 단계에 따라 달라짐.
* **면접 목적**: 지원 직무의 기본기, 문제 해결 과정, 경험의 깊이와 협업 방식 등을 확인하는 과정으로 이해하고 준비할 것.

### 지원 직무와 채용 수준에 맞춰 경험 설명하기

평가 기준은 회사·직무·신입/경력 구분에 따라 다르므로, 채용공고와 면접 안내를 먼저 확인할 것. 신입은 수업·팀 프로젝트에서도 본인의 판단과 학습 과정을 설명할 수 있음. 경력자는 담당 범위, 기술적 의사결정과 검증 결과를 구체적으로 제시할 것.

### 경험을 점검할 3가지 포인트

1. **문제 해결 흐름 (Troubleshooting)**

    * 문제가 발생한 조건을 어떻게 재현했고, 로그·측정값·비교 실험으로 원인 가설을 어떻게 좁혔는가?
    * 수정 후 같은 문제가 해결되었는지 어떻게 확인했으며, 남은 한계는 무엇인가?

2. **시스템 전체를 보는 시각 (Cross-functional Thinking)**

    * 본인의 담당 영역이 로봇 하드웨어(모터, 센서, 기구)와 소프트웨어(제어기, AI 추론)에 어떻게 연결되는가?
    * 다른 직군이나 팀원과 문제를 공유할 때 재현 조건과 측정 결과를 어떻게 전달했는가?

3. **기초 공학 지식의 탄탄함**

    * 사용한 알고리즘과 라이브러리의 기본 원리, 입력·출력, 적용 조건을 설명할 수 있는가?
    * 직접 확인한 내용과 추가 학습이 필요한 부분을 구분할 수 있는가?

## 2. 전공 및 실무 테스트 유형별 대응 전략

### (1) 전공 / 직무 PT (Presentation) 면접

* 알고리즘이나 제어 시스템 설계 과제를 풀고 설명하는 형태 등이 있으며, 준비 시간·자료 사용·발표 방식은 안내에 따라 확인할 것.
* **핵심 전략**: 요구사항과 제약 → 가정 → 대안 비교 → 선택 이유 → 검증 방법 순서로 설명할 것. 계산 결과뿐 아니라 설계가 어떤 조건에서 성립하는지, 어떤 한계가 있는지도 제시할 것.

### (2) 포트폴리오 발표 면접

* **핵심 전략**: 전체 발표 시간에 맞춰 배경을 짧게 설명하고, 본인의 역할과 판단에 시간을 배분할 것. 팀 전체 성과와 직접 담당한 설계·구현·검증 범위를 구분할 것.
* **경험 선택**: 본인의 판단과 기여가 잘 드러나는 문제를 선택할 것. 큰 실패 경험이 없어도 대안 선택, 구현 과정의 제약, 테스트와 개선 경험을 설명할 수 있음.
* **연습 방법**: 같은 프로젝트를 1분 요약과 상세 설명으로 각각 준비하고, 질문에 따라 필요한 부분을 확장해 설명할 것.

### (3) 코딩 테스트 및 화이트보드 코딩

* **실시간 면접**: 문제를 이해한 뒤 모호한 입력 조건과 제약을 질문할 것. 입력 조건 → 접근 방법 → 시간·공간 복잡도 → 구현 → 예제·경계 조건 검증 순서로 주요 판단을 공유할 것. 모든 생각을 계속 말하기보다 설명과 구현의 흐름을 맞출 것.
* **온라인 코딩 테스트**: 문제에 명시된 입력 범위, 출력 형식, 시간·메모리 제한을 먼저 확인할 것. 질문할 수 없는 환경에서는 명시된 조건을 기준으로 풀이하고, 허용되는 경계값과 예외 상황을 점검할 것.

## 3. 모르는 기술 질문을 받았을 때 3단계 대처법

익숙하지 않은 질문을 받으면 질문의 범위와 조건을 먼저 확인할 것. 알고 있는 사실, 가정에 따른 추론, 추가 확인이 필요한 내용을 구분해 설명할 것.

아래 문장은 답변 구조를 설명하는 예시임. A·B, `○○` 등의 표현은 실제 질문과 본인의 경험에 맞게 바꾸고, 근거가 없는 경우에는 추론을 억지로 이어가지 말 것.

1. **이해한 질문과 지식 범위 확인하기**

    * **개념은 알고 있지만 구현 경험이 없는 경우**: "말씀하신 B가 ○○ 상황에서 사용하는 방식인지 확인해도 될까요? 기본 개념은 알고 있지만 직접 구현한 경험은 없습니다."
    * **기본 개념도 익숙하지 않은 경우**: "해당 방식은 아직 학습하지 못했습니다. 관련해서 제가 알고 있는 ○○ 개념부터 설명드려도 될까요?"

2. **근거가 있는 범위에서 가정을 구분해 설명하기**

    * "제가 구현한 A에서는 ○○ 원리로 동작합니다. B에도 같은 조건이 적용된다면 △△를 예상할 수 있지만, 실제 동작은 확인이 필요합니다."
    * 두 방식에 같은 조건이 적용되는지 알 수 없다면 그 한계를 먼저 밝힐 것. 알고리즘 이름이나 유사한 경험만으로 동작 원리를 단정하지 말 것.

3. **확인할 내용과 검증 방법 제시하기**

    * "우선 기술 문서에서 알고리즘의 가정과 수식을 확인하겠습니다. 이후 같은 입력과 실행 조건에서 응답과 오차를 비교해 제 예상이 맞는지 검증하겠습니다."
    * 질문에 맞춰 확인할 자료, 비교할 조건과 지표를 구체적으로 제시할 것. 테스트 결과가 없는 상태에서는 예상과 검증된 결론을 구분할 것.

## 4. 로봇/AI 프로젝트 경험을 설명하는 핵심 포인트

### (1) 시뮬레이션과 실제 환경에서 확인한 범위 구분

* **실제 로봇 시험 경험이 있는 경우**: Isaac Sim, Gazebo 등 시뮬레이션과 실제 환경에서 달랐던 현상(센서 노이즈, 바퀴 미끄러짐, 통신 지연 등), 원인 가설, 검증 과정과 남은 한계를 설명할 것. 시도한 보정이나 튜닝이 효과가 있었는지도 같은 조건에서 비교할 것.
* **시뮬레이션 경험만 있는 경우**: 모델의 가정, 시험 조건, 확인한 결과와 실제 환경에서 추가로 검증해야 할 항목을 설명할 것. 실제 로봇에서 시험하지 않은 결과를 실물 검증 성과로 표현하지 말 것.

### (2) 성과는 검증 가능한 근거로 설명

* 측정값이 있다면 측정 환경, 비교 기준, 지표 정의, 반복 횟수를 함께 제시할 것. 수치가 없다면 구현 범위, 재현한 문제, 테스트 결과와 한계를 설명할 것. 측정하지 않은 수치나 개선율을 임의로 만들지 말 것.
* **시간 지표 구분**: 제어 주기, 제어 루프 실행 시간, 통신 지연, 주기의 변동(지터)은 구분해서 설명할 것. 제어 주기를 짧게 설정했다는 사실만으로 통신 지연이 줄었다고 판단할 수는 없음.
* **위치 지표 구분**: 회전 관절의 각도 오차, 직선 관절의 이동 거리 오차, 로봇 말단의 위치 오차 중 무엇을 측정했는지 명시할 것. 각도와 길이의 단위를 구분하고 평균값·최댓값 등 비교 지표도 통일할 것.

다음은 설명 방식의 예시이며, 실제 수행한 측정·검증 내용으로 바꿔 답할 것.

* **통신 성능**: "동일한 통신 부하에서 명령 전송부터 응답 수신까지의 지연을 측정했습니다. 패킷 구조 변경 전후의 평균값과 최댓값을 비교했습니다." 실제 답변에서는 측정값과 시험 조건을 함께 제시할 것.
* **위치 정확도**: "동일한 시험 자세에서 캘리브레이션 전후의 로봇 말단 위치 오차를 비교했습니다. 기준 위치의 측정 방법과 반복 횟수도 함께 정리했습니다." 실제 답변에서는 위치 오차의 정의와 측정 결과를 함께 제시할 것.
* **정량 성능 지표가 없는 경우**: "통신이 끊기는 조건을 재현하고, 재연결 후 데이터 수신이 다시 시작되는 것을 확인했습니다. 장시간 반복 시험은 아직 진행하지 못했습니다."

### (3) 면접 전 연습 체크리스트

* 지원 공고의 핵심 업무와 연결되는 경험을 골랐는가?
* 팀 전체 성과와 내가 담당한 설계·구현·검증 범위를 구분할 수 있는가?
* 기술 선택 이유와 검토한 대안을 설명할 수 있는가?
* 측정 조건·실패 사례·남은 한계를 설명할 수 있는가?
* 같은 프로젝트를 1분 요약과 상세 설명으로 각각 연습했는가?
